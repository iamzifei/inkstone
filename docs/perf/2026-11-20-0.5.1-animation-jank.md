# 0.5.1 — animation jank: what was measured, what changed (2026-11-20)

James: "some animations still feel janky — fix performance on Mac and iOS, then release."

## Method
- `scripts/make-bench-vault.py` — deterministic vault: 3,000 linked notes, four ~60 KB notes,
  a note embedding 12 full-size 2400×1600 PNGs, eight mid-sized notes to switch between.
- `App/Support/MainStallMonitor.swift` (DEBUG) — a background thread asks the main queue to
  run an empty block every 4 ms; any wait over one 60 Hz frame is time an animation stood still.
- `scripts/bench-stalls.sh ios|mac <out.tsv> [runs]` — drives the app through DemoDirector
  (switch notes ×24, open long notes ×12, type 30 characters + autosave, open the image note),
  optimised DEBUG builds, median of 3 runs. iPhone 18 Pro simulator; Mac app launched in the
  background (`open -g`).
- Causes found with `sample` on the running app, not guessed; a change that did not move the
  numbers or the samples was reverted.

Pitfall worth keeping: the first Mac baseline was inflated ~3–4× by **App Nap** (the app was
launched in the background; its main queue was woken late and the monitor counted the nap as a
stall — `sample` saw the main thread idle 90% of the time). The monitor now holds a
latency-critical activity; numbers below are from after that fix.

## Results (total main-thread time blocked beyond a frame; median of 3 runs)

| Segment | Mac before | Mac after | iOS before | iOS after |
|---|---|---|---|---|
| Switch notes ×24 | 1,144 ms | 815 ms | 384 ms | 247 ms |
| Open 60 KB note ×12 | 2,546 ms | 629 ms | 394 ms | 242 ms |
| — longest single stall | 243 ms | 79 ms | 66 ms | 46 ms |
| Note with 12 large images | 629 ms | 48 ms | 1,074 ms | 30 ms |
| — longest single stall | 338 ms | 64 ms | 1,090 ms | 47 ms |
| Typing ×30 + autosave | 53 ms | 17 ms | 0 | 0 |

Raw rows: `docs/perf/0.5.1-{before,after}-{mac,ios}.tsv`. Run-to-run noise on "switch" is about ±12%.

## What changed
1. **Mac: no whole-document layout before the view has a window.** `textView.string = text` in
   `makeNSView`, on a fresh zero-width view, went through the selection change into
   `setNeedsDisplayInRect:avoidAdditionalLayout:NO`, and TextKit filled glyphs and layout for the
   entire note — ~45% of main-thread time opening a long note. `InkstoneTextView` now passes
   `avoidAdditionalLayout: true` while `window == nil`.
2. **Draw passes stop at the laid-out text.** Each of the renderer's 12 passes asked for the
   on-screen box of every chip, rule and checkbox in the note, which made TextKit lay out the whole
   note on every redraw until background layout caught up. `EditorRenderer.drawableRange(for:)`
   lays out through the dirty rect (work drawing needs anyway) and limits the passes to text
   before `firstUnlaidCharacterIndex()`. Hit-testing is unchanged.
3. **Images decode off the main thread.** `AttachmentImageCache` reads only the header on the
   main thread, returns a blank placeholder of the exact point size (layout is final at once, no
   jump), decodes with ImageIO in a detached task, then posts `didDecode`; editors restyle once
   for any number of pictures landing together. PDFs and formats ImageIO cannot read keep the
   synchronous path.
4. **One highlight pass per open, not three.** The first pass now marks the index generation it
   used (the first `updateView` was restyling everything again), the width pass ignores the
   pre-layout call with no width, and a new editor starts at the width the last one settled on.

## Tried and reverted (no measured gain)
- Inspector `List` → `ScrollView`/`LazyVStack`: removed the NSTableView row rebuild from the
  samples, but SwiftUI's own layout took its place; switch time unchanged within noise.
- Scoping the menu commands' `.disabled(workspace.activeTab …)` into item views: the scene
  update under each switch remained (it is driven by window preferences such as the title).
- File-tree rows not observing the active tab (experiment only): within noise on iOS.

## Not done (candidates for a later pass, unmeasured here)
- iOS scrolling of notes over 40k characters: `visibleCharacters()` per scroll frame and a full
  restyle on leaving the styled range (audit item 4). Needs a scroll benchmark segment.
- Index publish on every autosave even when nothing changed: measured negligible at 3,000
  notes (typing segment above); revisit at 10k.
