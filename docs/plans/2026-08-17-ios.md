# iOS — 2026-08-17

Bring the iOS build from "compiles" to a usable app on iPhone and iPad, icon
included. The desktop side is finished, signed and notarised; this is the last
major piece.

## Where it actually stands (measured 2026-08-17, not assumed)

The handoff said iOS "compiles but has never run". Only the second half was
true — it did not compile either, because the debug hooks added over the last
few sessions are AppKit-only. Fixed, and then it ran for the first time.

What works, seen on an iPhone 17 Pro simulator:

  - Welcome screen: icon, cinnabar accent, both vault buttons
  - Sidebar: vault name, file list, the five section tabs
  - Vault opening and indexing

What does not:

| Gap | Evidence |
|---|---|
| Selecting a note does not open the editor | Note highlights, view stays on the sidebar |
| Every custom-drawn element is missing | Lines 227–1024 of `MarkdownEditorView` are `#if os(macOS)`; iOS has 161 lines with no drawing at all |

The second one is worse than it sounds. The highlighter is cross-platform, so it
collapses `- ` and `- [ ] ` markers to 0.01pt on iOS exactly as it does on macOS
— but nothing draws the replacement. **Bullets and checkboxes do not look wrong
on iOS; they are absent**, and the text they marked is silently unlabelled.

## Phases

### 1. Navigation — a note opens its editor

`NavigationSplitView` collapses to a stack on iPhone, and selection has to push
the detail column. Verify on both iPhone (stack) and iPad (three columns, plus
Slide Over widths).

**Done when:** launching with `INKSTONE_OPEN_NOTE=Home.md` shows the editor, and
tapping a note in the list does the same.

### 2. Custom drawing, made cross-platform

The bulk of the work. Roughly 800 lines currently behind `#if os(macOS)`:

  - `CaretMetrics` — pure metrics, should port as-is
  - Caret and selection — UIKit has no `drawInsertionPoint`; the caret is a
    subview, and selection drawing still goes through `NSLayoutManager`
  - Bullets, checkboxes, quote rules, heading rules, inline fills
  - Inline images, inline maths, table alignment
  - Mermaid — the offscreen `WKWebView` needs a host window on macOS; iOS has no
    equivalent trick and needs its own answer

Ordering: the metrics and the shape drawing first (they share one geometry
path), then images and maths, then Mermaid last since it may need a different
approach entirely.

**Done when:** a note containing every construct renders identically on both
platforms, compared screenshot to screenshot.

### 3. Touch

Not a port — these have no desktop equivalent:

  - Tapping a checkbox to toggle it (12pt is below the 44pt touch target; the
    tap area has to be larger than the drawn box)
  - A keyboard accessory row for Markdown syntax
  - Text selection handles against custom drawing
  - Dynamic Type

### 4. Icon

Three appearances (light, dark, tinted) already ship from
`Tools/generate-app-icon.py` and are in the asset catalog. Unverified on device:
tinted mode in particular must read through luminance alone. Check on the home
screen in all three modes, plus Settings and Spotlight sizes.

### 5. Distribution

Device registration and the iCloud container are already done for the team. Left
open deliberately until the app is worth installing.

## Verification

The simulator is scriptable end to end, which the Mac GUI never was:

    xcrun simctl install booted <app>
    SIMCTL_CHILD_INKSTONE_SCRATCH_VAULT=1 SIMCTL_CHILD_INKSTONE_OPEN_NOTE=Home.md \
      xcrun simctl launch booted com.orris.inkstone
    xcrun simctl io booted screenshot out.png

`INKSTONE_SCRATCH_VAULT` seeds a vault inside the app container and
`INKSTONE_OPEN_NOTE` opens a note in it — the note list is a navigation stack, so
without the second one nothing but the sidebar is ever on screen.

Screenshots go to the scratchpad, never to the repository.
