# 在桌面端集成 AI agent

**立项：** 2026-08-26。
**目标：** 右侧边栏一个对话面板，能对当前笔记和整个知识库提问、并在确认后落笔修改。

---

## 已经定了的（不要重开）

| 决定 | 选择 |
| --- | --- |
| 能力边界 | **完整 agent** —— 模型自己决定搜什么、读哪篇、改哪里，多轮循环直到任务完成 |
| 模型来源 | **BYOK**，key 存 Keychain。Anthropic + OpenAI + **任意 OpenAI 兼容端点**（覆盖 ccapi.ai / OpenRouter / 本机 Ollama） |
| 上下文 | 关键词搜索兜底 + **内嵌 Core ML 语义检索** + `@` 手动指定 + 默认带当前打开的文件 |
| 界面 | 右侧边栏，和大纲/反链共存 |
| 端上模型 | Foundation Models 做**辅助档**（改写、起标题、单篇摘要），复杂任务提示换云端 |

## 三个实测出来的硬约束

这一节是本计划里唯一不能靠推理得出的部分，全部是这台机器上跑出来的。

### 1. 复用用户的 Claude 订阅：不行，两条路都堵死

**官方明文**（Agent SDK overview，2026-08-26 读取）：

> Unless previously approved, Anthropic does not allow third party developers to offer
> claude.ai login or rate limits for their products, including agents built on the
> Claude Agent SDK.

那"不内嵌登录，只是启动用户本机已装的 `claude` CLI"呢？**沙盒挡死。**

| exec 目标 | 结果 |
| --- | --- |
| `/bin/echo` | ✅ |
| `/tmp/echo-copy` —— **同一个二进制**，仅路径不同 | ❌ |
| `~/.local/share/claude/versions/2.1.245`（Anthropic 签名，`Q6L2SF6YDW`） | ❌ |

加 `com.apple.security.temporary-exception.files.absolute-path.read-execute`、
精确到文件名、换 Developer ID 真证书重签 —— **三种条件下全部被拒**。
系统确实在处理这个 entitlement（它把我写的 `/tmp/` 从生效列表里剥掉了），但不放行。

⚠️ 报错是 `NSCocoaErrorDomain Code=4 "The file doesn't exist"`，**文件明明存在**。
沙盒拒绝访问时，文件对该进程就等于不存在。**这个报错描述的是"我打不开"，
不是"它不在"** —— 差点据此去排查路径。

**结论：不为此关闭沙盒。** 关了也拿不到订阅额度（官方本来就不允许），
只是白白丢掉沙盒。BYOK + 自定义端点是替代品：用户想省钱可以接自己的渠道。

### 2. Apple 的端上句向量做不了语义检索

`NLEmbedding.sentenceEmbedding` 不需要 Apple Intelligence、离线、免费，
本来是理想解。8 组成对样本实测：

```
相关 0.510  这个季度的营收目标是多少 / 本季度销售额预期
无关 0.271  这个季度的营收目标是多少 / 我家猫最近不爱吃饭
                    ↑ 无关的反而更近

相关均值 0.439   无关均值 0.335   间隔 -0.104   → 有重叠，单一阈值必然误判
```

**方向是反的**，8 组里 6 组如此。它是上一代静态词向量的平均，对词汇重叠敏感、
对语义不敏感。**不可用**，语义检索必须走真正的 sentence transformer。

n=8，样本是我自己造的；如果换成真实笔记标题结论可能没这么极端 ——
但"能不能用单一阈值分开"这个判据不依赖样本量，有重叠就是不能用。

### 3. 端上 LLM 存在，但默认关着

`FoundationModels.framework` 在 SDK 里，部署目标已经是 macOS 26.0，无需改动。
但 `SystemLanguageModel.default.availability` 在这台机器上返回
`unavailable(appleIntelligenceNotEnabled)` —— 不是不支持，是系统设置里没开。
**UI 必须处理这个状态**，而不是假设可用。

| 要用的 | 已经有的 |

最后一条是这个功能能做得快的主要原因：别人要为 chat 单独写一套 markdown 渲染，
我们复用阅读模式那一套，视觉和笔记天然一致。

## 分阶段

每个阶段结束都必须是**能用的东西**，不是半成品。

### 阶段 1 — 能对话　✅ 完成 08-26

- [x] `ModelProvider` 协议 + Anthropic / OpenAI 兼容两个实现（SSE 流式）
- [x] API key 进 Keychain（**不同步到其他设备**，理由见代码注释）
- [x] 设置面板：提供商、端点、模型、思考强度，含「检查」按钮实拉模型列表
- [x] 右侧栏 Assistant 标签，回复用 `ReadingView` 渲染 —— 和笔记同一套排版
- [x] 流式输出 + 停止按钮
- [x] 47 个单元测试 + `swift run provider-check` 实调两家 API，全过

**两个值得记的坑：**

1. **`URLSession.AsyncBytes.lines` 不能用来解 SSE。** Foundation 的
   `AsyncLineSequence` 按行切但**从不产出空行**，而空行正是 SSE 分发事件的信号。
   结果：整个响应的所有事件堆在一个 buffer 里、直到连接关闭才吐出来，
   两个 provider 都**一个字都收不到**。
   先证实了是 Foundation 的行为不是服务器的（原始响应里有 8 个 `\n\n`），
   再写 `SSELines` 自己按字节切。
   **47 个单元测试全绿，一个都抓不到** —— 它们都是手工喂行给 parser，
   而字节流和 parser 之间那道缝是唯一没有测试的地方。现在有了。

2. **`@Environment(AppSettings.self)` 编译通过，启动即 trap。**
   这个 app 只往 environment 注入 `Workspace`，settings 挂在它下面。
   读一个不存在的 environment 对象是**运行时断言，不是类型错误** ——
   没有任何一次构建或测试能发现，直到窗口打开。

**没能验证的**：面板长什么样、用起来什么感觉。用脚本驱动要截运行中的 Mac，
前两次截图带进了无关窗口里的私人内容，已删除。已确认的是：app 能起来不崩、
两个 provider 对真实端点能流式能调工具、累加器能把它们发的东西拼对。

### 阶段 2 — 能用工具（只读）　✅ 完成 08-26

- [x] 工具循环（tool_use → 执行 → tool_result → 继续），上限 12 轮
- [x] 四个只读工具：`search_notes`、`read_note`、`list_links`、`list_notes`
- [x] 工具调用折叠成一行「正在搜索 X」，可展开看原始参数和结果
- [x] 路径逃逸防护（`/etc/passwd`、`../`、`~/.ssh` 全部拒绝，有测试）
- [x] 15 个工具单元测试 + `swift run provider-check` 端到端跑真实 agent 循环

**端到端测试抓到了一个单元测试抓不到的东西，值得记：**

第一次跑，Anthropic 3 轮答对，**OpenAI 连搜三次全空，然后回答「您的笔记中没有相关内容」**
—— 而那篇笔记就在库里。

原因不在代码，在**我写的工具描述**里。我写的是：

> "Keep it short; two or three words match more than a sentence."

**正好写反了。** 搜索是**逐行**匹配（这样才能给出行号和高亮），所以每多一个词
是在**收窄**匹配范围。测试笔记的「乌龙茶」在第 1 行、「水温」在第 3 行，
多词查询必然落空。

改成把规则说清楚（"every word must appear on the same line, search ONE
distinctive word"），并在空结果时**指名下一步该搜哪个词**。同一个模型第二次尝试
就恢复了：多词失败 → 读提示 → 改用「乌龙茶」→ 找到 → 读全文 → 答对。

**工具描述是模型唯一的文档，写错一句话的表现和「库是空的」一模一样。**
而这个只有让真模型跑一遍才看得见 —— 15 个单元测试全绿的时候，它是坏的。

### 阶段 3 — 能编辑　✅ 完成 08-26

- [x] 写工具：`create_note`、`edit_note`（后者按精确文本替换，像 Claude Code 的 Edit）
- [x] **改动累积，不逐个弹窗** —— agent 跑完 → 输入框上方出现「N 处未保存的改动 · Review」
      → 弹出 diff → 逐 hunk 勾选 → 保存选中的
- [x] 32 个单元测试 + 两家模型的端到端验证（8/8 全绿）
- [x] 写操作走 `NoteStore` 同一条路径，落盘后自动重建索引

**核心不变式，两个，都有测试也都有端到端验证：**

| | |
| --- | --- |
| 全部接受 | 结果**逐字节等于**模型提议的内容 |
| 全部拒绝 | 文件**逐字节不变** |

第二条是整个 review 步骤赖以成立的东西 —— 拒绝了改动却发现文件被改了的人，
之后不会再相信任何一次 review。

**几个设计决定：**

1. **工具不碰磁盘，只进队列。** 端到端验证的正是这一点：让真模型改一篇笔记，
   它调了 `edit_note`、报告完成，而磁盘上的文件**一个字节都没变**。
2. **`read_note` 优先读未保存的改动。** 否则模型看到自己的编辑没生效，会再改一次
   —— 白花一轮，还多出一份要 review 的改动。
3. **同一篇笔记的多次编辑折叠成一个 diff，且是对磁盘内容的 diff。**
   不折叠的话，reviewer 看到的是「对一个从未存在过的中间版本」的差异。
4. **`edit_note` 要求精确匹配且只能匹配一次。** 匹配到 2 处直接拒绝并说明 ——
   近似匹配照样应用，正是编辑落到错误段落的方式，而那是用户自己写的东西。
5. **`create_note` 不覆盖已存在的笔记。** 模型有改笔记的工具，用 create 覆盖是
   值得报错的失误，不是值得满足的请求。

### 阶段 4 — 上下文
- `@` 提及：笔记、文件夹、当前选中文字
- 默认带上当前打开的文件（可关）
- 附件：图片（vision 模型）、文本文件
- **验收**：`@` 能补全出笔记，附件能被模型看到

### 阶段 5 — 语义检索
- 选型并实测一个 Core ML sentence transformer（候选 multilingual-e5-small）
- 索引落盘 + 随笔记改动增量更新
- 混合召回：关键词优先，语义补
- **验收**：问一个不含任何原文关键词的问题，能召回对的笔记
- ⚠️ **最大的不确定性在这**：模型体积（+100~400MB，现在整个 DMG 才几十 MB）、
  首次索引 8,852 篇的耗时、中英混排效果。**选型必须先实测再决定，不能先写代码**

### 阶段 6 — 端上模型辅助档
- `FoundationModels` 接进 `Provider` 协议
- `appleIntelligenceNotEnabled` 时给出可操作的引导，不是干瘪的报错
- 复杂任务（需要多轮工具）自动提示换云端
- **验收**：断网状态下能改写选中段落、生成标题

## 命名与品牌（官方有硬规定）

Agent SDK 文档的 branding 段落明确：

- ✅ 可以叫 "Claude"、"Powered by Claude"
