# 落地页的下载按钮 404 了四个版本

**报告：** 2026-08-25，用户点了落地页的下载按钮。
**状态：** 已修，根因已固化进脚本，已补测试并验证测试真的会红。

## 发生了什么

网站的下载按钮指向

```
https://github.com/iamzifei/inkstone/releases/latest/download/Inkstone.dmg
```

这个 URL 只有在 latest release 里**恰好有一个叫 `Inkstone.dmg` 的资产**时才解析得了。
`Tools/package-dmg.sh` 产出的是 `Inkstone-<版本>.dmg`（appcast 需要靠版本号区分），
我上传的也是那个名字。**没有任何一步把这两个名字对上。**

0.1.2 到 0.1.5，四个版本，按钮一直是 404。

## 为什么测试没测出来 —— 两层，都是我写的

站点有 62 个测试，其中一个就叫 `test_internal_links_resolve`。它长这样：

```python
for href in re.findall(r'href="([^"#]+)"', html):
    if href.startswith(("http://", "https://", "mailto:")):
        continue          # ← 下载链接从这里溜走了
```

1. **外链被显式跳过。** 这个测试的本意是"页面不要链到构建产物里没有的文件"，
   它确实做到了。但**整个站点存在的意义就是把人送到那个外链上**，而它是唯一
   一类从来没被检查过的链接。
2. **它只跑 `LandingPages.PAGES` 那两个页面。** 下载按钮在**首页**上，
   首页压根不在任何链接测试的范围里。

两层各自看都说得通，叠在一起就是：**站点最重要的那个链接，没有任何测试碰过它。**

这不是"测试写得不够多"（62 个不算少），是**测试的边界正好画在了要害外面**。
`if startswith("http"): continue` 那一行，在写的时候是一个合理的作用域限制；
它同时也是一个"以下内容不予检查"的声明，而那个声明从来没被复核过。

## 修了什么

### 1. 立刻 —— 给 v0.1.5 补上稳定名字的资产

```
Inkstone-0.1.5.dmg   ← appcast 用，每个版本一份，永久有效
Inkstone.dmg         ← 网站用，永远指向最新
```

实测：`curl -L -o /dev/null -w '%{http_code}'` 从 404 变成 **200**。

⚠️ 中途踩到一次：资产传上去了、`gh api .../releases/latest` 也列出了它，
但 URL **仍然返回 404**，持续了半分钟。是 GitHub CDN 缓存了之前的 404 响应。
差点据此判断"上传没生效"去重传。发布脚本里的重试就是为这个写的。

### 2. 根因 —— `Tools/release-mac.sh`

之前**没有 macOS 发布脚本**，每次都是手打 `gh release create`。
"再传一份稳定名字的"这一步只存在于我的记性里，所以它当然会漏。

新脚本每次发布都传**同一个文件的两个名字**，并且在退出前
**真的去 curl 那个网站在用的 URL**（带重试，绕开 CDN 缓存），不是 200 就退出码非零。

> `gh release upload` 成功只证明资产进了 release。
> 它不证明网站用的那个 URL 能解析 —— 那还取决于这个 release 是不是 latest、
> 名字是不是一个字符不差。**这正是之前静默失败的那一步。**

### 3. 测试 —— `ExternalLinks`（3 个）

| 测试 | 补的是哪个洞 |
| --- | --- |
| `test_the_download_link_is_a_real_file` | 单独、第一个断言下载链接。真发 HEAD 请求 |
| `test_our_own_links_resolve` | 站点上所有指向自己 GitHub 的链接 |
| `test_every_page_has_its_internal_links_checked` | 走**每一个** html，不只那两个落地页 |

断网 `skipTest`，404 `fail` —— 这个区分是有意的：网络不通不该让人以为链接坏了，
链接坏了也不该被当成网络不通糊弄过去。

`inkslab.app` 的绝对自链（canonical、hreflang）**故意不发网络请求**，
改成映射回本地构建产物检查（`test_absolute_self_links_point_at_pages_this_build_produces`）。
理由：那些链接指向的是**已部署**的站点，而本次新增的页面要等这个测试放行才会部署 ——
发请求会得到一个必然的假 404。

### 4. 验证测试本身有效

写完没有停在"63 个全绿"。把 `build.DOWNLOAD` 注入成一个明知不存在的资产名重跑：

```
→ 注入 404 后: FAILED（测试有效）
```

**绿色只证明当下没问题，不证明这个测试将来抓得住。** 这一步是后者。

## 记下来的那条

这次的错误不在任何一行代码里，在一行 `continue` 里。

写测试的时候，"我不检查什么"和"我检查什么"是同一个决定，但只有后半句会被写下来、
被 review、被数进"62 个测试"。前半句是隐式的，而**bug 全在前半句里**。

可操作的版本：**一个跳过条件（`continue` / `skip` / `if not ...: return`），
要在旁边写清楚被跳过的东西由谁来保证。** 写不出来，就说明没人保证。
