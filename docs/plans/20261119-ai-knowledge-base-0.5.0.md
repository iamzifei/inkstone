# Inkstone 0.5.0 — 重定位为给小白用的「AI 知识库」

**目标：** 打开就会用的 AI 知识库：引导建库 → 拖进任何东西（移动/复制）→ 自动整理（规则可在设置里用提示词自定义）→ 库里自动生成并维护 `AGENTS.md` / `README.md` / `SOURCE_OF_TRUTH.md` 三个入口文件；发 0.5.0（Mac + iOS），官网与 SEO 全面改成「AI 知识库 / AI 上下文管理」定位。

**不做（non-goals）：**
- 不做账号、不做服务器、不把文件默认发到云端（本机优先，云端模型须用户自带 key 且明确开启）。
- 自动整理永远不删除文件、不改写正文（只移动、重命名、补元数据；「删除」= 移到 `_归档/待删除/`）。
- 不放弃与 Obsidian 的兼容（库仍是普通文件夹 + Markdown），但它降为次要卖点。
- 不做 Android / Web。

## 已定决策（James，2026-11-19）
- 名字：英文商店名 `Inkstone: AI Knowledge Base`，中文 `Inkstone · AI 知识库`，繁体 `Inkstone · AI 知識庫`。
- AI：本机优先（Apple Intelligence，文件不离开设备）→ 无本机模型时用规则整理 → 用户填了自己的 API key 并开启后才用云端模型。
- 骨架文件夹名跟建库时的界面语言（中/繁/英），建好后不随界面语言变。
- 发布：0.4.0 先过审自动上架；0.5.0 做完再提交（Mac 同步发 Sparkle + Homebrew）。
- 拖入默认「复制」，可选「以后都这样」，设置里可改。
- PR：CI 绿 + 新上下文独立评审通过后我自己合（沿用 0.4.0 规则）。

## 阶段（每阶段：先写测试/验收 → 实现 → CI → 独立评审 → 合并）

### P1 核心：知识库蓝图 + 三个入口文件（InkstoneCore）
- `VaultBlueprint`：按语言生成骨架（00-收件箱 … _系统/整理规则.md、整理日志.md、文件索引.csv、重复记录.md）。
- `EntryFiles`：生成/更新 `AGENTS.md`、`README.md`、`SOURCE_OF_TRUTH.md`；**自动维护区块用标记包住**（`<!-- inkstone:auto:… -->`），区块外用户写的内容永远不动；内容取自实际目录树、规则文件和统计（不写死数字）。
- 验收：单测覆盖三语言骨架、幂等（重复运行不变）、用户手写内容保留、已有库（如詹有才这种结构）只补缺不覆盖。

### P2 引导建库（Mac + iOS）
- 首次打开（无库）→ 三步向导：「知识库就是一个文件夹」通俗解释 → 选位置（iCloud / 本机文件夹 / 用已有文件夹）+ 名字 → 生成骨架和入口文件 → 落在收件箱并提示「把东西拖进来」。
- 已有文件夹作为库：只补 `_系统/` 和入口文件，不搬动用户文件（除非用户点「帮我整理」，先出变更计划）。
- 验收：模拟器 + Mac 实拍截图；三语言；空库/已有库两条路径都有测试。

### P3 拖入：移动还是复制
- Mac：拖到窗口任意处 / 侧栏 / 收件箱；iPad：拖放；iPhone：「添加文件」（文件 App 选择器、照片）+ 已合入的分享扩展。
- 首次拖入弹「复制 / 移动」+「以后都这样」，默认复制；设置里可改。进收件箱后触发整理。
- 验收：文件、文件夹、多文件、同名冲突、大文件、iCloud 未下载文件都有测试；移动失败时不丢原件（先复制成功再删源）。

### P4 自动整理引擎（核心，本阶段最大）
- 按默认策略（见 `docs/plans/assets/默认整理策略.md`，即 James 给的策略原文）执行：识别类型（UTType + 文件头）→ 提取（PDF 文本、EXIF、OCR、音视频时长、Office/HTML 文本）→ SHA-256 精确去重；文本 SimHash、图片感知哈希近似去重 → 分类（用户规则 > 现有项目/领域 > 资料/素材 > 置信度 <0.7 进 `_待确认/`）→ 规范命名 → 补元数据（Markdown frontmatter；非文本写 `文件索引.csv` / `.meta.md`）→ 写日志。
- 分类器三档：本机模型（Foundation Models，经现有 `ModelProvider`）/ 规则（类型、扩展名、关键词、日期）/ 云端（用户 key + 开关）。
- **变更计划**：新库、涉及去重合并、或 >20 个文件 → 先出计划给用户确认；小批量直接做并记日志。
- **撤销**：每次整理一条批次，日志可完整回滚；界面一键撤销上一次整理。
- 维护：打开库时检查收件箱；「立即整理」按钮；整理报告（数字全部来自实际扫描）。
- 验收：属性测试「任何整理序列后文件总数与内容哈希集合不变（只移动）」「回滚后逐字节还原」；各类型样本 fixture；无模型时规则路径可用；`_待确认` 流程有界面。

### P5 设置
