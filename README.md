# Inkstone 墨砚

An Obsidian-class notes app for macOS 26 and iOS 26. Plain Markdown files on disk,
wikilinks, graph, canvas, daily notes — native SwiftUI, no Electron.

> full session context, the design rationale, and the open crash investigation.
> Work stopped on a `RenderBox` Metal abort that is very likely environmental —
> details in §4 there.

## Architecture

```
Inkstone.xcodeproj          generated by XcodeGen from project.yml
├── App/                    SwiftUI app, one target for macOS + iOS
│   ├── InkstoneApp.swift   scene, menu commands, resolved Style environment
│   ├── Model/              Workspace (central state), NoteDocument (autosave)
│   ├── Support/            Theme → SwiftUI/AppKit/UIKit bridging
│   └── Views/              Sidebar, Editor, Graph, Canvas, Calendar, Settings
└── Packages/InkstoneCore/  platform-agnostic engine, no SwiftUI
    ├── Vault/              Vault, VaultRegistry, VaultScanner, VaultWatcher, NoteStore
    ├── Markdown/           Frontmatter, SyntaxScanner, NoteParser
    ├── Index/              IndexSnapshot, IndexBuilder, LinkRewriter
    ├── Search/             fuzzy quick-switch + full-text with operators
    ├── Graph/              GraphData, deterministic force simulation
    ├── Canvas/             JSON Canvas 1.0 model
    └── Settings/           Theme, Typography, AppSettings
```

Two decisions worth knowing:

**The files on disk are the source of truth.** There is no database. A vault
Obsidian created opens in Inkstone and vice versa; app-specific state lives in a
hidden `.inkstone/` folder you can gitignore. This is also why rename rewrites
`[[links]]` across the vault — with no database, a broken link is permanent.

**The core has no UI framework dependency.** `InkstoneCore` imports Foundation
and Yams only, so parsing and indexing are unit-testable without a simulator, and
the same engine could back a CLI or a share extension later.

## Website

`inkslab.app` — source in [`site/`](site), built by `python3 site/build.py` into
`site/_site` and published to GitHub Pages by `.github/workflows/site.yml`. Eight
languages; the page structure lives in the generator and only the copy is
translated, so a missing key fails the build instead of dropping a section.

The hero recording and the screenshots are reproducible: `scripts/record-demo.sh`
drives a Debug build against `assets/demo-vault`, and `scripts/encode-demo.sh`
cuts it. Read the comment at the top of each — the constraints they work around
are not guessable.

## Building

```bash
brew install xcodegen        # the .xcodeproj is generated, not committed
xcodegen generate
open Inkstone.xcodeproj

# core engine only, no Xcode needed — fastest feedback loop
cd Packages/InkstoneCore && swift test
```

## Running it

```bash
xcodebuild -project Inkstone.xcodeproj -scheme Inkstone \
  -destination 'platform=macOS' -derivedDataPath .build-xcode build
open .build-xcode/Build/Products/Debug/Inkstone.app
```

Click **Open Folder as Vault** and point it at [`Samples/Inkstone Demo`](Samples)
— interlinked notes, CJK tags, a callout, a table, an unresolved link, and a
canvas. The sandbox has no standing access outside its container, so that manual
pick is the grant; the security-scoped bookmark restores it on later launches.

⚠️ This is where the app currently crashes on at least one machine. See
[HANDOFF.md §4](HANDOFF.md#4-the-open-bug--read-this-first).

## Open items

**iCloud entitlement is deferred.** `iCloud.com.orris.inkstone` doesn't exist in
the developer portal, and enabling the entitlement before the container exists
makes every local build fail to sign. The keys are commented in
`App/Resources/Inkstone.entitlements` with instructions; `createICloudVault()`
already shows an alert instead of failing silently. Create the container, then
uncomment.

**iOS is unrun.** It typechecks, but the UIKit editor path (tap-to-follow-link
hit testing, keyboard insets) has never executed. Expect to fix things there.

**Nobody has seen the UI.** Not one screenshot exists. Every visual claim in this
README is inferred from code, not observed.

**Attachments, image/video preview, and per-file-type sync filters** were
requested and are not started.

## Roadmap

- **Phase 2** — reading-mode renderer built on swift-markdown's AST (currently a
  dependency that's resolved but unused), image/PDF embeds, math via MathJax or
  SwiftMath.
- **Phase 3** — GitHub sync. iOS has no usable libgit2 story, so the plan is the
  GitHub Contents API with a local shadow index rather than real git.
- **Phase 4** — the plugin surface: templates, dataview-style queries, kanban,
  excalidraw-style drawing on canvas.
